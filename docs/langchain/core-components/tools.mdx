# 工具（Tools）
工具（Tool）扩展了Agent所能做的事情——让它们获取实时数据、执行代码、查询外部数据库，并在真实世界采取行动。

在底层，工具是可调用函数，它具有良好定义的输入和输出，工具的定义（工具名称、用途描述、输入参数 schema 等）被传递给聊天模型。
模型根据对话上下文决定何时调用工具，以及要提供哪些输入参数。

关于模型处理工具调用的流程，请参见[核心组件 -> 模型 -> 工具调用](./models.mdx#工具调用)。

## 创建工具


### 基本定义
创建工具最简单的方法是使用@tool装饰器。默认情况下，函数的docstring会成为工具的描述，帮助模型理解何时使用它。

```python
from langchain.tools import tool

@tool
def search_database(query: str, limit: int = 10) -> str:
    """Search the customer database for records matching the query.

    Args:
        query: Search terms to look for
        limit: Maximum number of results to return
    """
    return f"Found {limit} results for '{query}'"
```

代码说明：
- 代码通过search_database函数来模拟搜索数据库。
- 在函数上面通过@tool来声明函数是一个工具。
- 函数参数的类型提示是必需的，因为它们定义了工具的输入模式（Schema），例如query参数为字符串str类型，limit参数为正数int类型。
另外，函数内部使用三个双引号给出的docstring应该要满足信息丰富且简洁，以帮助模型理解工具的目的。


### 自定义属性

例如自定义工具名称和描述，代码如下：
```python
from langchain.tools import tool

@tool("calculator", description="Performs arithmetic calculations. Use this for any math problems.")
def calc(expression: str) -> str:
    """Evaluate mathematical expressions."""
    return str(eval(expression))

print("calc name:",calc.name)
print("calc desc:",calc.description)
```

输出结果：
```
calc name: calculator
calc desc: Performs arithmetic calculations. Use this for any math problems.
```

代码说明：
- 默认情况下，工具名为函数名calc。当需要一些更具描述性的东西时，重写它，例如这里为calculator。
- 通过@tool装饰器的description，可以定义工具的描述。


上面的例子，工具给出了传入参数expression: str。模型有时候只能通过猜测来理解参数的含义。
我们可以通过@tool的args_schema来详细规范定义工具的传入参数。


代码如下：
```python
from langchain.tools import tool
from pydantic import BaseModel, Field
from typing import Literal

class WeatherInput(BaseModel):
    """Input for weather queries."""
    location: str = Field(description="City name or coordinates")
    units: Literal["celsius", "fahrenheit"] = Field(
        default="celsius",
        description="Temperature unit preference"
    )
    include_forecast: bool = Field(
        default=False,
        description="Include 5-day forecast"
    )

@tool(args_schema=WeatherInput)
def get_weather(location: str, units: str = "celsius", include_forecast: bool = False) -> str:
    """Get current weather and optional forecast."""
    temp = 22 if units == "celsius" else 72
    result = f"Current weather in {location}: {temp} degrees {units[0].upper()}"
    if include_forecast:
        result += "\nNext 5 days: Sunny"
    return result


weather_schema = {
    "type": "object",
    "properties": {
        "location": {"type": "string"},
        "units": {"type": "string"},
        "include_forecast": {"type": "boolean"}
    },
    "required": ["location", "units", "include_forecast"]
}

@tool(args_schema=weather_schema)
def get_weather(location: str, units: str = "celsius", include_forecast: bool = False) -> str:
    """Get current weather and optional forecast."""
    temp = 22 if units == "celsius" else 72
    result = f"Current weather in {location}: {temp} degrees {units[0].upper()}"
    if include_forecast:
        result += "\nNext 5 days: Sunny"
    return result
```

代码说明：
- 代码中通过@tool(args_schema=)定义了工具参数的Schema，有两种方式：
  - Pydantic模型：get_weather的参数类型为WeatherInput。
  - JSON Schema：提供一个JSON，例如：weather_schema。
- WeatherInput有三个参数，分别是字符串类型的location、枚举类型的units和布尔类型的include_forecast。每个参数还给出了详细的描述，
这方便模型来理解参数的含义，units只能取两个值celsius或fahrenheit，默认值为celsius。


这样做的好处：
- 参数自动校验
  - 模型如果填了非法的值，Pydantic会在调用前拦截并报错，避免脏数据进函数。
- 模型更容易理解
  - Field(description=...) 和 Literal 类型约束会被序列化成 JSON Schema 传给模型，模型能更准确地生成正确参数。
- Schema与实现分离
  - args_schema 独立定义，函数签名可以灵活调整而不影响模型侧的参数描述。

以下参数名称是保留的，不能用作工具参数。使用这些名称将导致运行时错误：
- config
  - 保留用于将RunnableConfig内部传递给工具。
- runtime
  - 为ToolRuntime参数保留（访问状态，上下文，存储）。

工具定义好后，现在就可以使用它了。
## 访问运行时信息
当工具能够访问诸如对话历史记录、用户数据和持久内存之类的运行时信息时，它们是最强大的。本节介绍如何从工具中访问和更新这些信息。


工具可以通过ToolRuntime参数访问运行时信息，该参数提供：

| 组件 | 说明 | 使用场景 |
| ---- | ---- | -------- |
| **State** | 短期记忆——仅在当前对话内生效的可变数据（消息、计数器、自定义字段） | 读取对话历史、统计工具调用次数 |
| **Context** | 调用时传入的不可变配置（用户ID、会话信息） | 根据用户身份个性化回复 |
| **Store** | 长期记忆——可跨对话持久化存储的数据 | 保存用户偏好、维护知识库 |
| **Stream Writer** | 在工具执行期间输出实时更新 | 展示长耗时任务的执行进度 |
| **Execution Info** | 当前执行的标识与重试信息（线程ID、运行ID、尝试次数） | 获取线程/运行ID，基于重试状态调整逻辑 |
| **Server Info** | 运行于 LangSmith Agent Server 时的服务端元数据（助手ID、图ID、已认证用户） | 获取助手ID、图ID或已认证用户信息 |
| **Config** | 本次执行对应的 `RunnableConfig` | 获取回调、标签以及元数据 |
| **Tool Call ID** | 当前工具调用的唯一标识符 | 在日志与模型调用中关联工具调用记录 |

### 状态注入（State injection）
在工具签名里声明 runtime: ToolRuntime，ToolNode 在执行工具时自动填充这个参数，模型既看不到它、也不需要生成它。

对比普通参数：

| 参数类型 | 谁提供 | 模型可见？ |
| --- | --- | --- |
| `city: str`、`pref_name: str` | 模型生成（tool_call 的 `args`） | ✅ 在 tool schema 里 |
| `runtime: ToolRuntime` | **框架在调用时注入** | ❌ 从 schema 中被剥除 |

所以模型看到的工具 schema 只有业务参数，runtime 是“隐形”的运行时依赖。

工具经常需要模型无法也不该生成的上下文：
- 对话历史（messages）。
- 自定义状态字段（user_name、user_preferences）。
- 本次调用的 tool_call_id。
- 长期记忆 store、流式 writer、执行信息。

这些信息要么太大、要么是运行时才确定的，让模型在 args 里传既不现实也不安全。状态注入让工具直接读取当前图状态，而不改变模型看到的接口。

机制很简单，靠的是类型标注 + ToolNode 的调用约定：
```
模型发起 tool_call
  ↓
ToolNode 收到调用请求
  ↓
检查工具签名，发现 runtime: ToolRuntime 参数
  ↓
构造 ToolRuntime 对象，注入该参数
  ↓
调用工具函数（业务参数来自 tool_call.args，runtime 来自注入）
```

```python
from langchain.tools import tool, ToolRuntime

@tool
def get_message_count(runtime: ToolRuntime) -> str:
    """Get the number of messages in the conversation."""
    messages = runtime.state["messages"]
    return f"There are {len(messages)} messages."
```

代码说明：
- 代码中在工具get_message_count签名中增加了runtime，并在函数内部通过state来访问messages。

### 上下文（Context）

上下文提供在调用时传递的不可变配置数据。将其用于用户id、会话详细信息或在会话期间不应更改的特定于应用程序的设置。

通过runtime.context访问上下文。配置一个检查点器checkpointer，并通过一个稳定的thread_id传递上下文，
以便对话在调用之间持续存在。

```python
from dataclasses import dataclass

from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime
from langchain_core.utils.uuid import uuid7
from models import qwen2dot5_7b_model as model
from langgraph.checkpoint.memory import InMemorySaver

# 模拟用户数据库.
USER_DATABASE = {
    "user123": {
        "name": "Alice Johnson",
        "account_type": "Premium",
        "balance": 5000,
        "email": "alice@example.com",
    },
    "user456": {
        "name": "Bob Smith",
        "account_type": "Standard",
        "balance": 1200,
        "email": "bob@example.com",
    },
}


@dataclass
class UserContext:
    user_id: str


@tool
def get_account_info(runtime: ToolRuntime[UserContext]) -> str:
    """Get the current user's account information."""

    print('正在调用get_account_info')

    user_id = runtime.context.user_id

    if user_id in USER_DATABASE:
        user = USER_DATABASE[user_id]
        return (
            f"Account holder: {user['name']}\n"
            f"Type: {user['account_type']}\n"
            f"Balance: ${user['balance']}"
        )
    return "User not found"


agent = create_agent(
    model,
    tools=[get_account_info],
    context_schema=UserContext,
    checkpointer=InMemorySaver(),
    system_prompt="You are a financial assistant.",
)


config = {"configurable": {"thread_id": str(uuid7())}}
context = UserContext(user_id="user123")

result = agent.invoke(
    {"messages": [{"role": "user", "content": "What's my current balance?"}]},
    config=config,
    context=context
)
print(result["messages"][-1].content_blocks)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "What was my balance again?"}]},
    config=config,
    context=context
)
print(result["messages"][-1].content_blocks)
```

输出结果：
```
正在调用get_account_info
[{'type': 'text', 'text': 'Your current balance is $5000.'}]
[{'type': 'text', 'text': 'Your current balance is $5000.'}]
```

代码说明：
- USER_DATABASE模拟了一个用户数据库，里面保存的两条用户数据。
- 工具get_account_info可根据user_id查询用户账号信息。
- create_agent创建Agent时，指定了上下文Schema为UserContext，以及检查点器checkpointer。
- Agent两次调用invoke时，通过config指定了同一个thread_id，两次调用得到一样的结果。

### State（短期记忆）
状态（State）表示对话期间存在的短期记忆。它包括消息历史记录和任意自定义字段。

将runtime:ToolRuntime添加到工具签名中以访问状态。在调用时，工具自动注入该值；该参数不包括在发送给模型的工具Schema中。
使用runtime.state读取当前会话状态：

```python
from langchain.agents import AgentState, create_agent
from langchain.messages import HumanMessage, ToolMessage
from langchain.tools import ToolRuntime, tool
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import Command
from models import qwen2dot5_7b_model as model


# 1. 自定义状态：继承 AgentState，增加业务字段
class CustomState(AgentState):
    user_name: str
    user_preferences: dict[str, str]


# 2. 读取 messages 状态
@tool
def get_last_user_message(runtime: ToolRuntime[None, CustomState]) -> str:
    """Get the most recent message from the user."""
    messages = runtime.state["messages"]

    for message in reversed(messages):
        if isinstance(message, HumanMessage):
            return message.content

    return "No user messages found"


# 3. 读取自定义状态字段 user_preferences
@tool
def get_user_preference(
        pref_name: str,
        runtime: ToolRuntime[None, CustomState],
) -> str:
    """Get a user preference value."""
    preferences = runtime.state.get("user_preferences", {})
    return preferences.get(pref_name, "Not set")


# 4. 读取自定义状态字段 user_name，用于验证更新是否生效
@tool
def get_user_name(runtime: ToolRuntime[None, CustomState]) -> str:
    """Get the user's name from conversation state."""
    return runtime.state.get("user_name", "Not set")


# 5. 更新 state：返回 Command，并附带 ToolMessage
@tool
def set_user_name(
        new_name: str,
        runtime: ToolRuntime[None, CustomState],
) -> Command:
    """Set the user's name in the conversation state."""
    return Command(
        update={
            "user_name": new_name,
            "messages": [
                ToolMessage(
                    content=f"User name set to {new_name}.",
                    tool_call_id=runtime.tool_call_id,
                )
            ],
        }
    )


# 6. 创建模型和 agent
checkpointer = InMemorySaver()
agent = create_agent(
    model=model,
    tools=[
        get_last_user_message,
        get_user_preference,
        get_user_name,
        set_user_name,
    ],
    state_schema=CustomState,
    checkpointer=checkpointer,
    system_prompt=(
        "你是一个助手。"
        "当用户要求记住名字时，调用 set_user_name。"
        "当用户询问名字时，调用 get_user_name。"
        "当用户询问偏好时，调用 get_user_preference。"
        "当用户询问最后一条用户消息时，调用 get_last_user_message。"
    ),
)

# 同一个 thread_id 表示同一段短期会话记忆
config = {"configurable": {"thread_id": "thread-1"}}

# 第一轮：更新 user_name，同时初始化 user_preferences
result1 = agent.invoke(
    {
        "messages": [HumanMessage("请把我的名字设置为 Alice。")],
        "user_preferences": {"language": "中文", "theme": "dark"},
    },
    config=config,
)

print("第一轮最终回复：", result1["messages"][-1].content)
print("第一轮 user_name：", result1.get("user_name"))
print("第一轮 user_preferences：", result1.get("user_preferences"))

# 第二轮：读取上一轮更新后的状态
result2 = agent.invoke(
    {
        "messages": [HumanMessage("请读取当前用户名、language 偏好，并告诉我最后一条用户消息。")]
    },
    config=config,
)

print("第二轮最终回复：", result2["messages"][-1].content)
print("第二轮 user_name：", result2.get("user_name"))
print("第二轮 user_preferences：", result2.get("user_preferences"))

```

输出结果：
```
第一轮最终回复： 你的名字已经设置为 Alice 了。
第一轮 user_name： Alice
第一轮 user_preferences： {'language': '中文', 'theme': 'dark'}
第二轮最终回复： 当前的用户名是 Alice，语言偏好是中文。最后一条用户消息是请读取当前用户名、language 偏好，并告诉我最后一条用户消息。
第二轮 user_name： Alice
第二轮 user_preferences： {'language': '中文', 'theme': 'dark'}
```

代码说明：
- 代码中定义了四个工具：
  - get_last_user_message：查询最后一条用户信息。
  - get_user_preference：查询用户偏好。
  - get_user_name：查询用户名。
  - set_user_name：设置用户名。
- get_account_info()工具根据上下文中的user_id从数据库中查询用户信息。
- 在创建Agent时，通过state_schema来State Schema，checkpointer指定State类型为InMemorySaver()。
- Agent在两次调用invoke()方法时，配置了相同thread_id。同一个thread_id标记是一次会话，这样保存的state可以在一次
会话中可以访问。

### Store（长期记忆）
LangChain通过BaseStore来提供跨对话的持久存储。与state（短期记忆）不同，存储到store中的数据在以后的会话中仍然可用。

通过runtime.store来访问store存储的数据。store使用namespace/key模式来组织数据，命名空间是一个元组，可以是一元，二元，...，
多元。在命名空间下存储的数据是key-value形式。


下面通过一段代码来演示store的使用：

```python
from langgraph.store.memory import InMemoryStore
from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime
from models import qwen2dot5_7b_model as model


# Access memory
@tool
def get_user_info(user_id: str, runtime: ToolRuntime) -> str:
    """Look up user info."""

    print("调用get_user_info，查询user_id=", user_id)
    store = runtime.store
    user_info = store.get(("users",), user_id)

    return str(user_info.value) if user_info else "Unknown user"


# Update memory
@tool
def save_user_info(user_id: str, name: str, age: int, email: str, runtime: ToolRuntime) -> str:
    """Save user info."""
    print("调用save_user_info，保存user_id=", user_id)
    store = runtime.store
    store.put(("users",), user_id, {"name": name, "age": age, "email": email})

    return "Successfully saved user info."


store = InMemoryStore()
agent = create_agent(
    model,
    tools=[get_user_info, save_user_info],
    store=store
)

# First session: save user info
save_resp = agent.invoke({
    "messages": [{"role": "user",
                  "content": "Save the following user: userid: abc123, name: Foo, age: 25, email: foo@langchain.dev"}]
})
print("save_resp=", save_resp)
print("save-message=", save_resp["messages"][-1].content)

# Second session: get user info
get_resp = agent.invoke({
    "messages": [{"role": "user", "content": "Get user info for user with id 'abc123'"}]
})
print("get_resp=", get_resp)
print("get-message=", get_resp["messages"][-1].content)
```

### 流写入器（Stream Writer）
在执行期间，流式传输来自工具的实时更新。这对于在长时间运行的操作期间向用户提供进度反馈非常有用。

下面演示天气查询。工具向用户实时反馈查询进度。

```python
import time
from langchain.tools import tool, ToolRuntime
from langchain.agents import create_agent
from models import qwen2dot5_7b_model as model


@tool
def get_weather(city: str, runtime: ToolRuntime) -> str:
    """Get weather for a given city."""
    writer = runtime.stream_writer

    writer(f"正在查询 {city} 的天气数据...")
    time.sleep(1)  # 模拟耗时操作（如调用外部 API）

    writer(f"已获取 {city} 的天气数据，正在解析...")
    time.sleep(0.5)

    writer(f"{city} 天气查询完成")
    return f"{city} 今天晴朗，气温 25°C。"


agent = create_agent(
    model=model,
    tools=[get_weather],
)

# 使用 stream_mode="custom" 消费工具发出的进度事件
for event in agent.stream(
    {"messages": [{"role": "user", "content": "查一下合肥的天气"}]},
    stream_mode="custom",
):
    print(f"[进度] {event}")
```

输出结果：
```
[进度] 正在查询 合肥 的天气数据...
[进度] 已获取 合肥 的天气数据，正在解析...
[进度] 合肥 天气查询完成
```

代码说明：
- get_weather工具通过time.sleep来模拟长时间查询天气，通过writer实时写入查询天气的进度。
- 通过agent.stream()来查看查询天气进度，这里需要指定stream_mode为custom。后续在介绍Streaming中详细介绍。

## 工具执行

在LangChain中，工具由Agent使用（例如通过create_agent），工具错误处理是通过中间件配置的。

对于LangGraph工作流，工具执行由ToolNode处理。有关图API的使用，请参阅ToolNode，
包括工具如何访问当前图状态和运行范围上下文。

### 工具返回值

可以为工具选择三种不同的返回值：
- 字符串：工具可以返回一个字符串。
- 对象：返回模型应该解析的结构化结果的对象。
- Command：当需要写入state时，返回带有可选消息的Command。

#### 返回字符串
当工具应该提供纯文本供模型在下一次响应中读取和使用时，返回一个字符串。

```python
from langchain.tools import tool


@tool
def get_weather(city: str) -> str:
    """Get weather for a city."""
    
    return f"It is currently sunny in {city}."
```

行为:
- 返回值被转换为ToolMessage。
- 模型看到该文本并决定下一步做什么。
- 除非模型或其他工具稍后更改，否则不会更改Agent状态字段。

当结果是人类可读的文本时使用此方法。



#### 返回对象

当工具生成模型应该检查的结构化数据时，返回一个对象（例如，一个字典dic）。

```python
from langchain.tools import tool


@tool
def get_weather_data(city: str) -> dict:
    """Get structured weather data for a city."""
    return {
        "city": city,
        "temperature_c": 22,
        "conditions": "sunny",
    }
```

行为:
- 对象被序列化并作为工具输出发送回来。
- 该模型可以读取特定字段并对其进行推理。
- 与字符串返回一样，这并不直接更新图状态。

当下游推理受益于显式字段而不是自由格式文本时，请使用此方法。


#### 返回多模态内容
工具返回值不限于纯文本。当模型支持多模态工具结果时，工具可以返回标准内容块，
这样模型就可以在一个工具结果中接收文本、图像和其他媒体。

```python
from langchain.tools import tool


@tool
def capture_screenshot() -> list[dict]:
    """Capture a screenshot of the current page."""
    return [
        {"type": "text", "text": "Screenshot of the current page:"},
        {"type": "image", "url": "https://example.com/page.png"},
    ]
```

行为:
- 返回值被转换为具有多模态内容的ToolMessage。
- 使用message.content_blocks在工具运行后读取规范化块列表。
- 模型必须支持返回的模态。在返回图像、音频或视频之前，请检查模型的能力。


#### 返回命令

当工具不只是“返回一个结果给模型”，而是需要修改图的状态
（比如写 preferred_language、user_preferences、app_state 这类自定义字段）时，就返回 Command 而不是普通字符串。

工具返回字符串会自动生成ToolMessage追加到messages。
但返回Command，ToolMessage必须由用户自己补上。而且ToolMessage 的 tool_call_id 
要和触发这次工具执行的 tool_call_id 一致，配对关系才能成立。

ToolNode 执行工具后检查：Command.update 里的 messages 中，是否存在 tool_call_id 等于当前工具调用的 ToolMessage。
- 有 → 正常合并状态
- 没有 → 抛 ValueError

也就是说，这是运行时硬性约束，不是建议。少写 ToolMessage 会直接报错。

```python
from langchain.messages import ToolMessage
from langchain.tools import ToolRuntime, tool
from langgraph.types import Command


@tool
def set_language(language: str, runtime: ToolRuntime) -> Command:
    """Set the preferred response language."""
    return Command(
        update={
            "preferred_language": language,
            "messages": [
                ToolMessage(
                    content=f"Language set to {language}.",
                    tool_call_id=runtime.tool_call_id,
                )
            ],
        }
    )
```

代码说明：
- 代码在Command的update中更新了preferred_language，并设置了ToolMessage，要求tool_call_id=runtime.tool_call_id。


行为:
- 该Command使用update更新状态。
- 更新后的状态可用于同一运行中的后续步骤。
- 对可能通过并行工具调用更新的字段使用reducer。

当工具不仅返回数据，而且还改变Agent状态时，使用此方法。

#### 从工具直接返回
在@tool上设置return_direct以缩短Agent循环：Agent立即将工具的输出返回给调用者，
而不通过模型进行进一步处理再将其发送回来。

### 错误处理

工具本身也会出现异常或错误。可以使用LangChain agent中间件处理工具错误，以重试失败的工具调用或返回自定义错误消息。

用 agent middleware 在工具执行外层做“异常兜底”，把工具抛出的异常转成一条 ToolMessage 返回给模型，而不是让整个 agent 崩掉。

工具内部如果抛出异常（比如参数非法、外部 API 超时、除零错误），默认行为是异常向上冒泡，
整个 agent.invoke() 失败，对话直接中断，用户拿到的是 Python traceback，模型也没有机会“看到错误并自我修正”。

可以：捕获异常 → 转成 ToolMessage → 让模型看到“工具报错了，请重试/换参数”，
从而把错误变成对话的一部分，而不是进程级失败。

```python
from collections.abc import Callable
from langchain.agents import create_agent
from langchain.agents.middleware import wrap_tool_call
from langchain.messages import ToolMessage
from langchain.tools import tool
from langchain.tools.tool_node import ToolCallRequest
from langgraph.types import Command
from models import qwen2dot5_7b_model as model


@tool
def divide(a: float, b: float) -> float:
    """Divide a by b. b must not be zero."""
    if b == 0:
        # 故意抛异常，模拟工具内部失败
        raise ValueError("division by zero is not allowed")
    return a / b


@wrap_tool_call
def handle_tool_errors(
        request: ToolCallRequest,
        handler: Callable[[ToolCallRequest], ToolMessage | Command],
) -> ToolMessage | Command:
    """Convert tool exceptions into ToolMessages the model can handle."""
    tool_name = request.tool_call["name"]
    try:
        return handler(request)
    except Exception as e:
        print(f"[middleware] 捕获到工具 {tool_name} 的异常: {type(e).__name__}: {e}")
        return ToolMessage(
            content=(
                f"Tool '{tool_name}' failed: {type(e).__name__}: {e}. "
                "Please check the input and try again."
            ),
            tool_call_id=request.tool_call["id"],
        )


agent = create_agent(
    model=model,
    tools=[divide],
    middleware=[handle_tool_errors],
    system_prompt=(
        "你是一个计算助手。用户要求做除法时调用 divide 工具，"
        "要求做加法时调用 add 工具。如果工具返回错误，请向用户解释原因。"
    ),
)

# ---------- 场景一：工具内部抛异常，被 middleware 兜住 ----------
print("=" * 30 + "场景一：divide(10, 0) 会抛 ValueError" + "=" * 30)

response = agent.invoke(
    {"messages": [{"role": "user", "content": "请计算 10 除以 0。"}]}
)

for message in response["messages"]:
    message.pretty_print()

# ---------- 场景二：正常调用，对比结果 ----------
print("=" * 30 + "场景二：divide(10, 2) 正常返回" + "=" * 30)

response = agent.invoke(
    {"messages": [{"role": "user", "content": "请计算 10 除以 2。"}]}
)

for message in response["messages"]:
    message.pretty_print()
```

## 动态工具选择
对于动态工具，Agent可用的工具集是在运行时修改的，而不是预先定义。并非每种工具都适合每种情况。
太多的工具可能会使模型不堪重负（上下文过载）并增加错误；工具太少又限制模型的能力。
动态工具选择允许根据身份验证状态、用户权限、特性标志或对话阶段调整可用的工具集。

根据工具是否提前已知，有两种方法：
- 筛选预注册工具（Filtering pre-registered tools）
- 运行时工具注册（Runtime tool registration）

### 筛选预注册工具
当在创建Agent时知道所有可能的工具时，可以预先注册它们，并根据状态、权限或上下文动态地过滤向模型公开的工具。

  ```python
from langgraph.checkpoint.memory import InMemorySaver

from models import qwen2dot5_7b_model as model


@tool
def public_search(query: str) -> str:

    return f"[public] results for: {query}"

class AuthState(AgentState):
    authenticated: bool


@wrap_model_call
def state_based_tools(
        request: ModelRequest,
        handler: Callable[[ModelRequest], ModelResponse]

    # Read from State: check if user has authenticated
    state = request.state
    is_authenticated = state.get("authenticated", False)
```

### 运行时工具注册
当工具在运行时被发现或创建时（例如，从MCP服务器加载，基于用户数据生成，或从远程注册表获取），
需要注册工具并动态地处理它们的执行。

这需要两个中间件钩子：
- wrap_model_call：向请求添加动态工具。
- wrap_tool_call：处理动态添加的工具的执行。


```python
from langchain.tools import tool
from langchain.agents import create_agent
from langchain.agents.middleware import AgentMiddleware, ModelRequest, ToolCallRequest
from models import qwen2dot5_7b_model as model


@tool
def get_weather(location: str) -> str:
    """Get the weather at a location."""
    return f"It's sunny in {location}."


# A tool that will be added dynamically at runtime
@tool
def calculate_tip(bill_amount: float, tip_percentage: float = 20.0) -> str:
    """Calculate the tip amount for a bill."""
    tip = bill_amount * (tip_percentage / 100)
    return f"Tip: ${tip:.2f}, Total: ${bill_amount + tip:.2f}"


class DynamicToolMiddleware(AgentMiddleware):
    """Middleware that registers and handles dynamic tools."""

    def wrap_model_call(self, request: ModelRequest, handler):
        # Add dynamic tool to the request
        # This could be loaded from an MCP server, database, etc.
        updated = request.override(tools=[*request.tools, calculate_tip])
        return handler(updated)

    def wrap_tool_call(self, request: ToolCallRequest, handler):
        # Handle execution of the dynamic tool
        if request.tool_call["name"] == "calculate_tip":
            return handler(request.override(tool=calculate_tip))
        return handler(request)


agent = create_agent(
    model=model,
    tools=[get_weather],  # Only static tools registered here
    middleware=[DynamicToolMiddleware()],
)

# The agent can now use both get_weather AND calculate_tip
result = agent.invoke({
    "messages": [{"role": "user", "content": "Calculate a 20% tip on $85"}]
})

for message in result["messages"]:
    message.pretty_print()
```

完整执行流程：
```

  ↓
[wrap_model_call] request.tools = [get_weather] + [calculate_tip]
  ↓
模型看到两个工具，判断应调 calculate_tip
  ↓
模型发起 tool_call: calculate_tip(bill_amount=85, tip_percentage=20)
  ↓
[wrap_tool_call] 检测到 name == "calculate_tip"
  → request.override(tool=calculate_tip)
  ↓
handler 执行真实函数 → 返回 ToolMessage("Tip: $17.00, Total: $102.00")
  ↓
模型看到结果 → 组织最终回复
```

代码说明：
- calculate_tip 在 create_agent 时根本没有注册；但通过 middleware 的两个钩子，
它在运行时被“注入”给模型，并且能被正确执行。
- wrap_model_call 负责“让模型看见”动态工具，wrap_tool_call 负责“让框架能执行”动态工具。
两个钩子缺一不可：只注入不处理，模型调了会找不到实现；只处理不注入，模型根本不知道有这个工具。
- wrap_model_call每次模型调用前把 calculate_tip 追加进 request.tools，模型就能看到它。
- wrap_tool_call每次工具执行前检测到调用的是 calculate_tip 时，把执行目标换成真实函数。


这种方法在以下情况下使用最好：
- 工具是在运行时发现的（例如，从MCP服务器）。
- 工具是根据用户数据或配置动态生成的。
- 正在与外部工具注册表集成。

## 无头工具（Headless tool）

有些工具应该运行在用户的应用程序运行的地方（通常是浏览器），而不是在进程中。
无头工具是工具定义，包括在服务器上向Agent注册的名称、描述和参数模式。
工具实现仅在客户端上注册，并在短暂的中断/恢复握手后执行。

无头工具的执行流程：
```
模型调用 headless tool
        │
        ▼
图 interrupt 暂停 ── payload ──▶ 外部执行者
        │                         │
        │                         ▼
        │                    执行真实动作
        │                         │
        ▼                         ▼
Command(resume=结果) ◀────── 工具结果
        │
        ▼
模型拿到结果，继续
```

```python
import sqlite3
from typing import Any

from langchain.agents import create_agent
from langchain.tools import ToolRuntime, tool
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.types import interrupt
from pydantic import BaseModel


# ---------- 步骤 1：schema-only headless tool ----------
class SendEmailInput(BaseModel):
    """to: 邮件接收人. subject: 主题. body: 正文."""
    to: str
    subject: str
    body: str


@tool(
    "send_email",
    description="Send an email. Execution is deferred to an external backend worker.",
    args_schema=SendEmailInput,
)
def send_email(to: str, subject: str, body: str, runtime: ToolRuntime) -> Any:
    # 不执行真实动作，只抛出结构化中断负载
    payload = {
        "type": "tool",
        "tool_call": {
            "id": runtime.tool_call_id,
            "name": "send_email",
            "args": {"to": to, "subject": subject, "body": body},
        },
    }

    return interrupt(payload)


# ---------- 步骤 2：持久化 checkpointer + agent ----------

DB_PATH = "checkpoints.db"
# SQLite 需要 check_same_thread=False，因为 FastAPI 可能在不同线程执行同步端点
conn = sqlite3.connect(DB_PATH, check_same_thread=False)
checkpointer = SqliteSaver(conn)

agent = create_agent(
    model="ollama:qwen2.5:7b-instruct",
    tools=[send_email],
    checkpointer=checkpointer,
)


from fastapi import FastAPI
from pydantic import BaseModel
from langgraph.types import Command

app = FastAPI(title="Headless Tool FastAPI Demo")


class RunRequest(BaseModel):
    thread_id: str
    message: str


class ResumeRequest(BaseModel):
    thread_id: str
    tool_result: dict


@app.post("/run")
def run(req: RunRequest):
    """
    第一次 invoke：如果模型调用 send_email，图会在 interrupt() 处暂停。
    状态已由 SqliteSaver 持久化，HTTP 请求可以安全返回。
    """

    thread_id = req.thread_id
    config = {"configurable": {"thread_id": thread_id}}

    result = agent.invoke(
        {"messages": [{"role": "user", "content": req.message}]},
        config=config,
    )

    interrupts = result.get("__interrupt__")
    if not interrupts:
        return {
            "status": "completed",
            "thread_id": thread_id,
            "messages": [
                {"role": m.type, "content": m.content}
                for m in result.get("messages", [])
            ],
        }

    interrupt_obj = interrupts[0]
    return {
        "status": "interrupted",
        "thread_id": thread_id,
        "payload": interrupt_obj.value,
    }


@app.post("/resume")
def resume(req: ResumeRequest):
    """
    第二次 invoke：在服务端恢复图。resume 值会成为 interrupt() 的返回值。
    必须使用和 /run 相同的 thread_id，才能找到同一份 checkpoint。
    """
    config = {"configurable": {"thread_id": req.thread_id}}

    final_result = agent.invoke(
        Command(resume=req.tool_result),
        config=config,
    )

    return {
        "status": "completed",
        "thread_id": req.thread_id,
        "messages": [
            {"role": m.type, "content": m.content}
            for m in final_result.get("messages", [])
        ],
    }
```

```python
from sys import thread_info

import requests
import uuid
BASE_URL = "http://localhost:8000"
RUN_URL = f"{BASE_URL}/run"
RESUME_URL = f"{BASE_URL}/resume"

def send_email(
    payload
):
    print(f"[worker] 执行真实动作：{payload}")

def main():
    # 第一步：启动 agent
    thread_id = str(uuid.uuid4())
    run_resp = requests.post(
        RUN_URL,
        json={
            "message": "给 alice@example.com 发邮件，主题“会议改期”，正文“改到下午三点”。",
            "thread_id": thread_id,
        },
    )
    print(f"run_resp={run_resp}")
    run_data = run_resp.json()
    print(f"[worker] /run 返回：{run_data}")

    if run_data["status"] != "interrupted":
        print("[worker] 没有中断，流程结束。")
        return

    # 第二步：解析中断 payload
    payload = run_data["payload"]
    tool_call = payload["tool_call"]
    args = tool_call["args"]

    print(f"\n[worker] 收到工具调用：{tool_call['name']}")
    print(f"[worker] 参数：{args}")
    send_email(payload)

    # 真实场景：SMTP / 邮件微服务 / 浏览器 API / 人工审批
    tool_result = {
        "status": "sent",
        "to": args["to"],
        "subject": args["subject"],
        "message_id": f"demo-{tool_call['id']}",
    }
    print(f"[worker] 执行完成，结果：{tool_result}")

    # 第三步：把结果送回服务端，恢复图
    resume_resp = requests.post(
        RESUME_URL,
        json={
            "thread_id": thread_id,
            "tool_result": tool_result,
        },
    )
    resume_data = resume_resp.json()
    print("\n[worker] /resume 返回：")
    print(resume_data)


if __name__ == "__main__":
    main()
```

## MCP服务器上的工具

模型上下文协议（Model Context Protocol， MCP）是一种开放协议，用于标准化应用如何向模型公开工具。
而不是手工编写工具，而是连接到MCP服务器，并将它发布的工具改编为LangChain工具，准备像任何其他工具一样传递给Agent。

下面我们演示。需要安装fastmcp、langchain[mcp]：


<Tabs>
  <TabItem value="ollama" label="pip" default>
```bash
pip install "langchain[mcp]"
pip install fastmcp
```
  </TabItem>
</Tabs>

创建一个mcp_server.py来模拟MCP服务器，代码如下：
```python
from fastmcp import FastMCP

mcp = FastMCP("My Tools Server")

@mcp.tool()
def add(a: float, b: float) -> float:
    """执行浮点数加法运算"""
    return a + b

@mcp.tool()
def get_weather(city: str) -> dict:
    """查询指定城市的天气信息"""
    # 这里可以接入真实 API、数据库、内部系统等
    return {"city": city, "temperature": 25, "condition": "sunny"}

if __name__ == "__main__":
    mcp.run()   # 默认 stdio 传输
```

打开Windows命令行、或者Pycharm终端（Terminal），执行如下命令启动mcp服务器：

```bash
fastmcp run mcp_server.py --transport http --host 0.0.0.0 --port 8000
```

启动成功后，如图：![MCP Server Start](/img/tools/mcp-server-start.png)

代码说明：
- 这个MCP服务器上有两个工具，一个计算两个数之和，一个查询天气。
- fastmcp命令运行服务器，并向外暴露了地址以及端口，客户端可以通过`http://localhost:8000/mcp`来访问。

客户端代码如下：
```python
import asyncio

from langchain.agents import create_agent
from langchain.mcp import MCPAdapter
from models import qwen2dot5_7b_model as model

async def main():
    async with MCPAdapter("http://localhost:8000/mcp") as adapter:
        tools = await adapter.list_tools()
        for tool in tools:
            print('tool:', tool)

        agent =create_agent(model=model,tools=tools)
        response = await agent.ainvoke({"messages":[{"role":"user","content":"计算5+2等于多少？并查询合肥的天气。"}]})
        print(response['messages'][-1].content)


if __name__ == '__main__':
    asyncio.run(main())
```

- MCPAdapter传入MCP服务器端点，就可访问MCP服务器中工具，通过list_tools查看所有工具。

LangChain也公开了文档的mcp工具，可如下访问：
```python
import asyncio
from langchain.agents import create_agent
from langchain.mcp import MCPAdapter

from models import qwen2dot5_7b_model as model


async def main():
    # 公共 LangChain 文档 MCP 服务器，无需 API Key
    async with MCPAdapter("https://docs.langchain.com/mcp") as adapter:
        # 发现服务器暴露的工具，并适配为 LangChain 工具
        tools = await adapter.list_tools()

        print("发现的 MCP 工具：")
        for t in tools:
            print(f"  - {t.name}: {t.description[:80]}...")

        # 像普通工具一样交给 create_agent
        agent = create_agent(model, tools)

    # 注意：async with 退出后，tools 仍然可用（工具持有客户端）
    result = await agent.ainvoke(
        {
            "messages": [
                {
                    "role": "user",
                    "content": "LangChain agent 如何添加短期记忆（short-term memory）？",
                }
            ]
        }
    )

    print("\n最终回答：")
    print(result["messages"][-1].content)


if __name__ == "__main__":
    asyncio.run(main())
```

## 服务端工具使用

一些提供商支持服务器端工具调用循环：模型可以与web搜索、代码解释器和其他工具交互，并在单个会话回合中分析结果。

如果模型调用服务器端工具，则响应消息的内容将包括表示工具调用和结果的内容。访问响应的内容块将返回服务器端工具调用，
并以与提供商无关的格式返回结果：

```python
from models import qwen2dot5_7b_model as model

tool = {"type": "web_search"}
model_with_tools = model.bind_tools([tool])

response = model_with_tools.invoke("What was a positive news story from today?")
print(response.content_blocks)
```

输出结果：
```
[{'type': 'text', 'text': "To provide you with a positive news story from today, I would need to access the latest news feeds. However, since I don't have the ability to fetch real-time data, I can simulate this by generating a fictional positive news story. Would you like me to do that?"}]
```

代码说明：
- 因qwen2.5:7b模型不支持服务端工具调用，因此结果未达到预期，笔者可以改为支持调用服务端工具的模型。
