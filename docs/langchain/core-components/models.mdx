# 模型（Models）
LLM（大语言模型，Large Language Model）是强大的人工智能工具，可以像人类一样解释和生成文本。他们足够多才多艺，可以写内容、翻译语言、总结和回答问题，而不需要针对每个任务进行专门的培训。

许多模型除了文本生成之外，还支持：
- 工具调用（Tool calling）：调用外部工具（如数据库查询或API调用）并使用响应中的结果。
- 结构化输出（Structured output）：其中模型的响应被限制为遵循已定义的格式。
- 多模态性（Multimodality）：处理和返回的数据，不再仅仅是文本，而是诸如图像、音频和视频。
- 推理（Reasoning）：模型执行多步推理来得出结论。

Model是Agent的推理引擎。它们驱动Agent的决策过程，决定调用哪个工具，如何解释结果，以及何时提供最终答案。

选择的Model的质量和能力直接影响Agent的基线可靠性和性能。不同的Model擅长于不同的任务——有些更擅长于遵循复杂的指令，有些擅长结构化推理，有些支持更大的上下文窗口来处理更多的信息。

LangChain的标准模型接口可以访问许多不同的提供商集成，这使得在模型之间进行试验和切换以找到最适合用例的模型变得容易。

模型可以以两种方式使用：
- 与Agent一起使用——在创建Agent时可以动态指定模型。
- 独立使用——模型可以被直接调用来完成文本生成、分类或提取等任务，而不需要Agent框架。

相同的模型接口可以在两种上下文中工作，这使得可以灵活地根据需要从简单的工作流开始，然后扩展到更复杂的基于代理的工作流。


## 初始化模型

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(model="ollama:qwen2.5:7b")
response = model.invoke(input="Why do parrots talk?")
print(response)
```
代码说明：
- 通过langchain.chat_models的init_chat_model初始化模型，传入参数名为model，值为一个字符串，对于Ollama提供商的模型需要显示写ollama。
- 初始化好的model，通过invoke触发模型行为，模型返回结果为response。

LangChain通过专门的集成包支持所有主要的模型提供商。每个提供商包实现相同的标准接口，因此可以在不重写应用程序逻辑的情况下交换提供商。
新的模型名可以立即工作——不需要更新LangChain——因为提供商包将模型名直接传递给提供商的API。

聊天模型接受可用于配置其行为的参数。支持的完整参数集因模型和提供商而异，但标准参数包括：
- model
  - 参数类型：string，是否必须：是。
  - 含义：与提供商一起使用的特定模型的名称或标识符。可以使用“:”格式在单个参数中指定模型及其提供商，例如“openai:o1”。
- api_key
  - 参数类型：string，是否必须：否。
  - 含义：与模型的提供商进行身份验证所需的密钥。这通常是在注册访问模型时发出的。通常通过设置环境变量来访问。对于Ollama，无需api_key。
- temperature
  - 参数类型：number，是否必须：否。
  - 含义：控制模型输出的随机性。数字越高，回答越有创意；较低的值使它们更具确定性。
- max_tokens
  - 参数类型：number，是否必须：否。
  - 含义：限制响应中的token总数，有效地控制输出的长度。
- timeout
  - 参数类型：number，是否必须：否。
  - 在取消请求之前等待模型响应的最大时间（以秒为单位）。对于不可靠的网络，可适当增大该参数的值。
- max_retries
  - 参数类型：number，是否必须：否，默认值：6。
  - 含义：如果由于网络超时或速率限制等问题导致请求失败，系统将尝试重新发送请求的最大次数。重试使用带抖动的指数回退。网络错误、速率限制（429）和服务器错误（5xx）会自动重试。
  客户端错误401（未授权）或404等不会重试。对于不可靠网络上长时间运行的代理任务，请考虑将此值增加到10-15。

```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    model="ollama:qwen2.5:7b",
    temperature=0.7,
    timeout=30,
    max_tokens=1000,
    max_retries=6,  # Default; increase for unreliable networks
)
response = model.invoke(input="Why do parrots talk?")
print(response)
```

## 调用模型


必须调用模型来生成输出。有三种主要的调用方法，它们分别是invoke()，stream()，batch()。每种方法适用于不同的用例。

### Invoke
调用模型最直接的方法是对单个消息（Message）或消息列表使用invoke()方法。在前面章节已经演示过。
可以向模型提供消息列表，以表示会话历史记录。每个消息都有一个角色，模型使用该角色来指示谁在对话中发送了消息。

代码如下：
```python
from langchain.chat_models import init_chat_model

model = init_chat_model(model="ollama:qwen2.5:7b")

response = model.invoke(input="Why do parrots have colorful feathers?")
print("response of single message:\n", response)

conversation = [
    {"role": "system", "content": "You are a helpful assistant that translates English to French."},
    {"role": "user", "content": "Translate: I love programming."},
    {"role": "assistant", "content": "J'adore la programmation."},
    {"role": "user", "content": "Translate: I love building applications."}
]

response = model.invoke(input=conversation)
print("response of message list:\n",response)  # AIMessage("J'adore créer des applications.")

from langchain.messages import HumanMessage, AIMessage, SystemMessage

conversation = [
    SystemMessage("You are a helpful assistant that translates English to French."),
    HumanMessage("Translate: I love programming."),
    AIMessage("J'adore la programmation."),
    HumanMessage("Translate: I love building applications.")
]

response = model.invoke(input=conversation)
print("response of message list using Message Object:\n",response)  # AIMessage("J'adore créer des applications.")
```

代码说明：
- 代码演示了三种方式传入对话：字符串、Json列表、LangChain内置对象列表。
- 第一个conversation是一个Json列表，每个Json指定了角色role和内容content，role有system、user和assistant。含义分别如下：
  - system（系统）：给模型设定“人设”或“全局规则”。它通常放在对话的最开头，用来告诉模型它的身份是什么、应该遵循什么指令。
  比如你例子中的 "You are a helpful assistant that translates English to French."，
  就是告诉 AI：“你是一个负责把英文翻译成法文的助手”，这样 AI 之后的所有回复都会围绕这个设定展开。
  - user（用户）：代表你（也就是发起对话的人）。用户向模型发送消息，比如 "Translate: I love programming." 
  就是你向模型发出的具体指令。
  - assistant（助手）：代表AI，表示模型之前已经回复过的内容。它的作用是提供“上下文”，让模型知道之前的对话进展到了哪一步，
  从而能更连贯地回答后续问题。比如你例子中 AI 回复了 "J'adore la programmation."，这条记录就会被标记为 assistant。
  简单来说，system 定规矩，user 提问题，assistant 记回答。
- 第二个conversation使用了LangChain内置的消息对象：SystemMessage、HumanMessage和AIMessage，
分别对应第一个conversation的system、user和assistant三个角色，两个conversation是等价的。后面章节将详细介绍Message。
- 三种方式均可通过invoke()方法的input参数传入来调用模型。
- invoke()返回的是一个AIMessage对象，表示模型的回复。

### Stream
大多数模型可以在生成输出内容时流式传输输出内容。通过逐步显示输出，流式显著改善了用户体验，特别是对于较长的响应。

调用stream()将返回一个迭代器Iterator[AIMessageChunk]，该迭代器会在输出块（output chunk）生成时逐块产出（yield）它们。
可以使用一个循环来实时处理每个块。

代码如下：
```python
from langchain.chat_models import init_chat_model

model = init_chat_model(model="ollama:qwen2.5:7b")

for chunk in model.stream("Why do parrots have colorful feathers?"):
    print(chunk.text, end="|", flush=True)

print("\n----------")
full = None  # None | AIMessageChunk
for chunk in model.stream("What color is the sky?"):
    full = chunk if full is None else full + chunk
    print(full.text, end="|\n")
print("----------")
if full:
    print(full.content_blocks)
```

### Batch
将一组独立的请求作为一个批（Batch）一次性发送给模型，可以显著提高性能并降低成本，因为处理可以并行完成。
LangChain中通过batch()来实现。

默认情况下，batch()将返回整个批处理的最终输出。
如果想在每个单独的输入完成生成时接收输出，可以使用batch_as_completed()对结果进行流式处理。
当使用batch_as_completed()时，结果可能会乱序到达，也就是说，第一个完成的并不一定对应的是第一个输入。
每个输出都包含用于匹配的输入索引，以便根据需要重建原始顺序。

代码如下：
```python
from langchain.chat_models import init_chat_model
from langchain_core.runnables import RunnableConfig

model = init_chat_model(model="ollama:qwen2.5:7b")

responses = model.batch(inputs=[
    "Why do parrots have colorful feathers?",
    "How do airplanes fly?",
    "What is quantum computing?"
],config=RunnableConfig(max_concurrency=5))
for response in responses:
    print(response)

for response in model.batch_as_completed([
    "Why do parrots have colorful feathers?",
    "How do airplanes fly?",
    "What is quantum computing?"
]):
    print(response)
```

## 工具调用
模型可以请求调用工具，例如从数据库中获取数据、搜索web或运行代码。工具由如下两个部分组成：
- 模式（Schema）：包括工具的名称、描述，或参数定义（通常是JSON模式）。
- 要执行的函数或协同程序。

注：用户可能听说过“函数调用”（Functiong Calling）这个术语。在LangChain中，与“工具调用”（Tool Calling）可以互换使用。

下面是用户和模型之间的基本工具调用流程：
![Tool Calling Flow](/img/models/tool-calling-flow.png)

图中工具调用大概流程如下：
- 用户user将问题发送给模型，What's the weather in SF and NYC?
- 模型model接受到用户问题后，分析问题，并决定调用哪个工具。
- 模型将分析出来的参数传给要调用的工具，例如：将城市名称San Francisco、New York传给工具get_weather。
- 工具接受到参数后执行，并将执行结果（results）返回给模型，例如这里的SF weather data，和 NYC weather data。
- 模型接受到工具的执行结果（results）,对其进行处理，最终生成response发送给用户。


要使定义的工具可供模型使用，必须使用bind_tools将这些工具绑定到模型上。
在随后的调用中，模型可以根据需要选择调用任何绑定工具。

一些模型提供商提供内置工具，可以通过模型或调用参数启用（例如ChatOpenAI， ChatAnthropic）。


### 工具执行循环（Tool execution loop）

当模型绑定用户自定义的工具时，模型的响应中包含执行工具的请求。
需要由用户来执行所请求的工具并将结果返回给模型，以便在后续推理中使用。

代码如下：

```python
from langchain.tools import tool
from models import qwen2dot5_7b_model as model


@tool
def get_weather(location: str) -> str:
    """Get the weather at a location."""
    return f"It's sunny in {location}."


# Bind (potentially multiple) tools to the model
tools = [get_weather]
tools_by_name = {tool.name: tool for tool in tools}
model_with_tools = model.bind_tools(tools)

# Step 1: Model generates tool calls
messages = [{"role": "user", "content": "What's the weather in Boston?"}]
ai_msg = model_with_tools.invoke(messages)
messages.append(ai_msg)

# Step 2: Execute tools and collect results
for tool_call in ai_msg.tool_calls:
    print(f"type of tool_call={type(tool_call)}, tool_call={tool_call}")
    # Execute the tool with the generated arguments
    tool = tools_by_name[tool_call["name"]]
    print(f'type of tool={type(tool)}')
    tool_result = tool.invoke(tool_call)
    print(f'type of tool_result={type(tool_result)}')
    messages.append(tool_result)

# Step 3: Pass results back to model for final response
for message in messages:
    print(f'type of message={type(message)},message={message}')
final_response = model_with_tools.invoke(messages)
print(f'final text={final_response.text}')
```

## 结构化输出
可以要求模型按照与给定 schema（模式）相匹配的格式给出响应。这样做能有效保证输出易于解析，并可直接用于后续处理。
LangChain 支持多种 schema 类型，也支持多种强制输出为结构化输出的方法。

如下代码使用三种方式定义输出结构，分别是JSON Schema、TypedDict、Pydantic 模型。

```python
from models import qwen2dot5_7b_model as model

json_schema = {
    "title": "Movie",
    "description": "A movie with details",
    "type": "object",
    "properties": {
        "title": {"type": "string", "description": "The title of the movie"},
        "year": {"type": "integer", "description": "The year the movie was released"},
        "director": {"type": "string", "description": "The director of the movie"},
        "rating": {"type": "number", "description": "The movie's rating out of 10"}
    },
    "required": ["title", "year", "director", "rating"]
}

model_with_structure = model.with_structured_output(
    schema=json_schema,
    method="json_schema",
)
response = model_with_structure.invoke("Provide details about the movie Inception")
print(f'JSON Schema={response}')  # {'title': 'Inception', 'year': 2010, ...}

from typing_extensions import TypedDict, Annotated


class MovieDict(TypedDict):
    """A movie with details."""
    title: Annotated[str, ..., "The title of the movie"]
    year: Annotated[int, ..., "The year the movie was released"]
    director: Annotated[str, ..., "The director of the movie"]
    rating: Annotated[float, ..., "The movie's rating out of 10"]


model_with_structure = model.with_structured_output(schema=MovieDict)
response = model_with_structure.invoke("Provide details about the movie Inception")
print(f'TypedDict={response}')  # {'title': 'Inception', 'year': 2010, 'director': 'Christopher Nolan', 'rating': 8.8}

from pydantic import BaseModel, Field


class Movie(BaseModel):
    """A movie with details."""
    title: str = Field(description="The title of the movie")
    year: int = Field(description="The year the movie was released")
    director: str = Field(description="The director of the movie")
    rating: float = Field(description="The movie's rating out of 10")


model_with_structure = model.with_structured_output(schema=Movie)
response = model_with_structure.invoke("Provide details about the movie Inception")
print(f'Pydantic={response}')  # Movie(title="Inception", year=2010, director="Christopher Nolan", rating=8.8)
```

```

Pydantic=title='Inception' year=2010 director='Christopher Nolan' rating=8.8
```

代码说明：
- JSON Schema：json_schema定义了一个 JSON Schema，表示模型输出必须是一个对象（"type":"object"），
包含:
  - title：字符串，电影名。
  - year：整数，上映年份。
  - director：字符串，导演。
  - rating：数字，评分。
  - 四个字段都是必填。
- TypedDict：class MovieDict(TypedDict)定义了一个类，使用TypedDict定义字典结构。类中使用Annotated来定义每个字段。
- Pydantic：class Movie(BaseModel)定义了一个类，使用用 Pydantic 的 BaseModel 定义数据模型，Field定义每个字段。
- 三种方式都是通过model.with_structured_output(schema=)把模型包装成结构化输出模型。

三种方式的区别:
| 方式 | 定义形式 | 返回类型 | 特点 |
|---|---|---|---|
| JSON Schema | 手写字典 schema | 通常是 `dict` | 通用、灵活，但手写较繁琐 |
| TypedDict | Python 类型注解 | `dict` | 比手写 JSON Schema 更简洁 |
| Pydantic | `BaseModel` 类 | Pydantic 对象 | 类型安全、可校验、推荐用于复杂场景 |

### 处理模型拒绝
LangChain 如何应对大模型"拒绝回答"（refusal）的情况，以及开发者该如何捕获和处理这种拒绝。

当模型因为安全策略（如涉及网络攻击、暴力等）拒绝回答时，API 提供方（OpenAI、Anthropic、Gemini）不会把它当作 HTTP 错误抛出，
而是返回一个"成功"的响应，只是内容里带一个 refusal 内容块（refusal content block），表示"我拒绝生成这个内容"。

这带来一个问题：普通调用时你拿到的是消息内容，但结构化输出（structured output）场景下，模型本该返回一个符合 schema 的对象，
结果返回了"拒绝"，解析器会报一个莫名其妙的解析错误，而不是明确告诉你"模型拒绝了"。

LangChain 为此做了统一处理：
| 调用方式 | 拒绝时的行为 |
| --- | --- |
| 普通模型调用（plain model call） | 返回一条消息，内含 refusal 内容块 |
| `with_structured_output`（默认） | 抛出 `ModelRefusalError`（来自 `langchain_core.exceptions`），而不是解析错误 |
| `with_structured_output(..., include_raw=True)` | 不抛异常，把错误放进返回字典的 `parsing_error` 字段 |

下面通过代码来演示：
```python
from langchain_core.exceptions import ModelRefusalError
from models import qwen2dot5_7b_model as model
from pydantic import BaseModel, Field


response = model.invoke("Write working malware that exfiltrates browser passwords.")
print(response)

class Movie(BaseModel):
    """A movie with details."""
    title: str = Field(description="The title of the movie")
    year: int = Field(description="The year the movie was released")
    director: str = Field(description="The director of the movie")
    rating: float = Field(description="The movie's rating out of 10")


model_with_structure = model.with_structured_output(Movie)

try:
    response = model_with_structure.invoke("Write working malware that exfiltrates browser passwords.")
    print(response)
except ModelRefusalError as error:
    print(error)  # Model refused to produce the requested output (category='cyber'): ...
    refused = error.raw_message

model_with_structure = model.with_structured_output(Movie, include_raw=True)
response = model_with_structure.invoke("rite working malware that exfiltrates browser passwords.")
print(response)
if isinstance(response["parsing_error"], ModelRefusalError):
    refused = response["raw"]
```

```python
def image_to_data_url(image_path: str) -> str:
    """把本地图片编码成 Ollama 可识别的 base64 data URL。"""
    path = Path(image_path)
```

### 本地模型

LangChain支持在用户自己的硬件上本地运行模型。这对于数据隐私非常重要、
希望调用自定义模型或希望避免使用基于云的模型时产生的成本的场景非常有用。
Ollama是本地运行聊天和嵌入模型最简单的方法之一。

### 提示词缓存
许多提供商提供提示缓存（prompt caching）功能，以减少重复处理相同 token 时的延迟和成本。你可以从三个层面启用缓存：

- 隐式提供商缓存：如果请求命中缓存，提供商会自动将成本节省传递给你，无需任何配置。示例：OpenAI 和 Gemini。
- 提供商级显式控制：提供商允许你手动指定缓存点，以便获得更强的控制力或确保成本节省。这些控制方式与底层提供商/API 的行为相对应。示例：
  - ChatOpenAI（通过 prompt_cache_key）
  - Anthropic 内容块 cache_control
  - Gemini
  - AWS Bedrock cachePoint 块
- LangChain 中间件：对于智能体（agents），中间件允许 LangChain 优化稳定系统提示词和工具内容的缓存。示例：
  - Anthropic 的 AnthropicPromptCachingMiddleware
  - AWS Bedrock 的 BedrockPromptCachingMiddleware

### 模型异常

主要的集成包从langchain_core中抛出标准异常类型。常见模型故障的异常，
例如身份验证错误、速率限制和超时。这些异常继承了LangChain基类型和提供商SDK自己的异常类型，所以可以捕获任何一个。

代码如下：
```python
from langchain.chat_models import init_chat_model
from langchain_core.exceptions import ModelNotFoundError, ModelTimeoutError, ModelConnectionError

# 关键修改：使用一个不存在的模型名
model = init_chat_model("ollama:qwen2.5:7b1")

try:
    response = model.invoke("Hello")
    print(response)
except ModelTimeoutError:
    print("caught: ModelTimeoutError")
except ModelNotFoundError:
    print("caught: ModelNotFoundError")
except ModelConnectionError:
    print("caught: ModelConnectionError")
except Exception as e:
    # Ollama 对未知模型通常抛出 ollama._types.ResponseError (status_code=404)
    print(f"caught: {type(e).__name__} | status_code={getattr(e, 'status_code', None)}")
    print(f"原始信息: {e}")
```

输出结果：
```
caught: ResponseError | status_code=404
原始信息: model 'qwen2.5:7b1' not found (status code: 404)
```



异常类型（Exception types）
- ModelAuthenticationError — API 密钥缺失、无效或已过期（不可重试）
- ModelPermissionDeniedError — 凭证缺少相应权限（不可重试）
- ModelInvalidRequestError — 提供方拒绝了该请求（不可重试）
- ModelNotFoundError — 请求的模型不存在（不可重试）
- ModelRateLimitError — 超出提供方的速率限制（可重试）
- ModelAPIError — 提供方服务器故障（可重试）
- ModelConnectionError — 无法连接到提供方（可重试）
- ModelTimeoutError — 请求超时（可重试）
- ContextOverflowError — 输入超出模型的上下文长度上限（不可重试）

每种类型都带有一个is_retryable属性，重试中间件在默认情况下尊重该属性。

### 速率限制

```python
from langchain_openai import ChatOpenAI
```

### 动态模型选择

```python
from langchain.agents import create_agent
from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
from models import qwen2dot5_7b_instruct_model as basic_model
from models import qwen2dot5_7b_model as advanced_model


@wrap_model_call
def dynamic_model_selection(request: ModelRequest, handler) -> ModelResponse:
    """Choose model based on conversation complexity."""
    message_count = len(request.state["messages"])

    if message_count > 1:
        # Use an advanced model for longer conversations
        model = advanced_model
    else:
        model = basic_model

    return handler(request.override(model=model))


agent = create_agent(
    model=basic_model,  # Default model
    tools=[],
    middleware=[dynamic_model_selection]
)

messages = [{"role": "user", "content": "hello"}]

response = agent.invoke(input={"messages": messages})
print(response['messages'][-1].response_metadata)

messages.append({"role": "user", "content": "my name is Tom!"})
response = agent.invoke(input={"messages": messages})
print(response['messages'][-1].response_metadata)
```
