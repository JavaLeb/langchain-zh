# 概览

## 基本概念

先看如下公式：
```
Agent = Model + Harness
```

![Agent Concept](/img/agents/agent-concept.png)

- Model
  - 大模型 / 基础模型，负责理解、推理、生成、规划下一步动作。它能阅读文本、写代码、做推理、决定下一步做什么，但它本身并不知道：
哪些工具能调用、哪些操作被允许、任务进行到哪一步、失败了怎么重试、结果是否安全。
- Harness
  - 模型之外的工程系统，负责上下文、记忆、工具调用、权限、护栏、日志、恢复等。它是补充Model这些能力的一层。它通常包括：
    - 上下文与记忆管理：保存对话状态、任务进度、历史决策。
    - 工具调用：让模型能搜索、读文件、查数据库、调 API、执行代码。
    - 权限与护栏：限制模型能访问哪些资源，拦截危险操作。
    - 任务编排：把目标拆成步骤，控制执行循环。
    - 可观测性：记录模型用了什么 Prompt、调了什么工具、返回了什么。
    - 错误恢复：工具超时、格式错误、调用失败时重试、回退或请求人工确认。
- Agent
  - 一个真正能“干活”的智能体，由模型驱动、能感知环境、调用工具、执行任务并持续推进目标的系统。

所以这个公式想表达的是：模型Model不是 Agent。模型决定 Agent “能想到什么”，Harness 决定 Agent “能不能安全、稳定、可审计地把事情做完”。

如果把 Agent 比作一辆车：
- Model 是发动机：提供动力；
- Harness 是方向盘、刹车、仪表盘、变速箱和安全系统：控制它怎么跑、跑多快、什么时候停；
- Agent 才是整辆车：能真正上路完成运输任务。


![Agent ReAct](/img/agents/agent-react.png)

这张图展示了一个 AI Agent 的核心工作循环（ReAct Loop），生动地解释了模型（Model）如何通过与外部工具（Tools）的交互来解决复杂问题。
结合我们刚才聊过的 Agent = Model + Harness 理论，这张图完美诠释了 Model 是如何在 Harness 的辅助下工作的。
这个流程可以看作是一个智能体的“思考-行动-观察”闭环：
- request (请求)：
  - 这是起点。用户或系统向 Agent 提交一个任务或问题，例如：“帮我查一下今天合肥的天气，并提醒我带伞。”
- model (模型)：
  - 这是 Agent 的“大脑”。它接收到请求后，开始思考。它会判断：要完成这个任务，我需要什么信息？我需要执行什么操作？
- action (行动)：
  - 模型决定要采取一个行动。它自己不会直接去查天气，而是会生成一个调用工具的指令。这就像大脑指挥手去拿尺子。
在这个例子里，模型会发出一个“查询天气工具”的请求，并带上“合肥”和“今天”作为参数。
- tools (工具)：
  - 这是 Agent 的“手和脚”，是它与外部世界连接的桥梁。它接收来自模型的 action 指令，并真正去执行。
在这里，天气查询工具会联网，向气象数据接口发起请求。
- observation (观察)：
  - 这是工具执行完毕后返回的需要被模型观察的“结果”。模型需要“看到”或“观察”到这次行动的结果，才能进行下一步判断。
在这里，工具返回了一个 observation：“合肥今天晴转多云，有小雨，气温 18-25℃”。这个信息会被反馈给模型。
- Loop (循环迭代)：
  - 模型接收到 observation 后，会将其与之前的记忆和任务目标结合，再次进行思考。
它会分析：“哦，有小雨，所以用户需要带伞。任务完成了吗？是的。现在我需要生成最终回复。”
在某些更复杂的任务中，模型可能需要调用多个工具，进行多次“action -> observation”的循环。核心思想：ReAct 模式。
这个循环被称为 ReAct (Reasoning + Acting) 模式，即 “推理+行动”。
推理 (Reasoning)：发生在 model 内部，决定下一步该做什么。
行动 (Acting)：通过调用 tools 来与外部世界互动。
- result (结果)：
  - 当模型判断任务已经完成，它会停止调用工具，直接生成一个最终的答案给到用户。
在这里，最终结果是：“合肥今天天气晴转多云，预计有小雨，出门请记得带伞。”



这张图的核心价值在于它揭示了 大模型本身能力有限，但通过连接工具并形成一个工作循环，就能变成一个能完成实际任务的强大 Agent。这也再次印证了 Harness（在这里体现为围绕这个循环的所有东西：提示符、工具和任何塑造模型行为的中间件等。）的重要性。
