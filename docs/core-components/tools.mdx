# 工具
工具（Tool）扩展了Agent所能做的事情——让它们获取实时数据、执行代码、查询外部数据库，并在真实世界采取行动。

在底层，工具是可调用函数，它具有良好定义的输入和输出，这些输入和输出被传递给聊天模型。模型根据对话上下文决定何时调用工具，
以及要提供哪些输入参数。

## 创建工具


### 基本定义
创建工具最简单的方法是使用@tool装饰器。默认情况下，函数的docstring会成为工具的描述，帮助模型理解何时使用它。

```python
from langchain.tools import tool

@tool
def search_database(query: str, limit: int = 10) -> str:
    """Search the customer database for records matching the query.

    Args:
        query: Search terms to look for
        limit: Maximum number of results to return
    """
    return f"Found {limit} results for '{query}'"
```

代码说明：
- 代码通过search_database函数来模拟搜索数据库。
- 在函数上面通过@tool来声明函数是一个工具。
- 类型提示是必需的，因为它们定义了工具的输入模式（Schema），例如query参数为字符串str类型，limit参数为正数int类型。
另外，函数内部使用三个双引号给出的docstring应该是信息丰富且简洁的，以帮助模型理解工具的目的。


### 自定义属性

例如自定义工具名称和描述，代码如下：
```python
from langchain.tools import tool

@tool("calculator", description="Performs arithmetic calculations. Use this for any math problems.")
def calc(expression: str) -> str:
    """Evaluate mathematical expressions."""
    return str(eval(expression))

print("calc name:",calc.name)
print("calc desc:",calc.description)
```

输出结果：
```
calc name: calculator
calc desc: Performs arithmetic calculations. Use this for any math problems.
```


### 模式定义

上面的例子，工具的参数通过函数参数指定。模型有时候只能通过猜测来理解参数的含义。
我们还可以通过@tool的args_schema来详细规范定义工具的参数。


代码如下：
```python
from langchain.tools import tool
from pydantic import BaseModel, Field
from typing import Literal

class WeatherInput(BaseModel):
    """Input for weather queries."""
    location: str = Field(description="City name or coordinates")
    units: Literal["celsius", "fahrenheit"] = Field(
        default="celsius",
        description="Temperature unit preference"
    )
    include_forecast: bool = Field(
        default=False,
        description="Include 5-day forecast"
    )

@tool(args_schema=WeatherInput)
def get_weather(location: str, units: str = "celsius", include_forecast: bool = False) -> str:
    """Get current weather and optional forecast."""
    temp = 22 if units == "celsius" else 72
    result = f"Current weather in {location}: {temp} degrees {units[0].upper()}"
    if include_forecast:
        result += "\nNext 5 days: Sunny"
    return result
```

代码说明：
- 代码中通过@tool(args_schema=WeatherInput)定义了工具get_weather的参数类型为WeatherInput。
- WeatherInput有三个参数，分别是字符串类型的location、枚举类型的units和布尔类型的include_forecast。每个参数还给出了详细的描述，
这方便模型来理解参数的含义，units只能取两个值celsius或fahrenheit，默认值为celsius。


这样做的好处：
- 参数自动校验
  - 模型如果填了非法的值，Pydantic会在调用前拦截并报错，避免脏数据进函数。
- 模型更容易理解
  - Field(description=...) 和 Literal 类型约束会被序列化成 JSON Schema 传给模型，模型能更准确地生成正确参数。
- Schema与实现分离
  - args_schema 独立定义，函数签名可以灵活调整而不影响模型侧的参数描述。

以下参数名称是保留的，不能用作工具参数。使用这些名称将导致运行时错误：
- config
  - 保留用于将RunnableConfig内部传递给工具。
- runtime
  - 为ToolRuntime参数保留（访问状态，上下文，存储）。

工具定义好后，现在就可以使用它了。

### 长期记忆（Store）
LangChain通过BaseStore来提供跨对话的持久存储。与state（短期记忆）不同，存储到store中的数据在以后的会话中仍然可用。

通过runtime.store来访问。store使用namespace/key模式来组织数据，下面通过一段代码来演示store的使用：

```python
from langgraph.store.memory import InMemoryStore
from langchain.agents import create_agent
from langchain.tools import tool, ToolRuntime
from langchain.chat_models import init_chat_model


# Access memory
@tool
def get_user_info(user_id: str, runtime: ToolRuntime) -> str:
    """Look up user info."""
    store = runtime.store
    user_info = store.get(("users",), user_id)

    return str(user_info.value) if user_info else "Unknown user"


# Update memory
@tool
def save_user_info(user_id: str, name: str, age: int, email: str, runtime: ToolRuntime) -> str:
    """Save user info."""
    store = runtime.store
    store.put(("users",), user_id, {"name": name, "age": age, "email": email})

    return "Successfully saved user info."


model = init_chat_model(model="ollama:qwen2.5:7b")

store = InMemoryStore()

agent = create_agent(
    model,
    tools=[get_user_info, save_user_info],
    store=store
)

# First session: save user info
save_resp = agent.invoke({
    "messages": [{"role": "user",
                  "content": "Save the following user: userid: abc123, name: Foo, age: 25, email: foo@langchain.dev"}]
})
print("save=", save_resp)
print("save-message=",save_resp["messages"][-1].content)

# Second session: get user info
get_resp = agent.invoke({
    "messages": [{"role": "user", "content": "Get user info for user with id 'abc123'"}]
})
print("get=", get_resp)
print("get-message=",get_resp["messages"][-1].content)
```

State和Store对比：
| 对比项 | State | Store |
| ---- | ---- | ---- |
| 性质 | 临时、易变 | 持久、跨对话 |
| 作用范围 | 仅存在于当前对话（Current Conversation）的进程中 | 跨对话（Across Conversations）。 |
| 生命周期 | 当对话结束、会话重启或进程终止时，State 中的数据通常会重置或丢失。 | 数据被持久化保存（通常写入数据库），即使对话结束、系统重启，数据依然存在。 |
| 典型用途 | 记录当前对话的消息历史（Conversation History）。追踪当前流程的执行进度（如：计数器、当前步骤）。存储为了完成当前任务而临时生成的中间数据。 | 保存用户的长期偏好设置（如：用户喜欢用摄氏度还是华氏度）。维护一个长期更新的知识库或用户画像。记住用户在上次对话中说过的关键信息。 |
